## ISO/IEC 19249

A Organização Internacional para Padronização (ISO) e a Comissão Eletrotécnica Internacional (IEC) criaram a ISO/IEC 19249. Nesta tarefa, abordaremos brevemente a ISO/IEC 19249:2017 Tecnologia da informação - Técnicas de segurança - Catálogo de princípios arquitetônicos e de design para produtos, sistemas e aplicações seguras. O objetivo é ter uma ideia melhor do que as organizações internacionais ensinariam sobre princípios de segurança.

A ISO/IEC 19249 lista cinco princípios arquitetônicos:

1.  **Separação de Domínio (Domain Separation):** Todo conjunto de componentes relacionados é agrupado como uma única entidade; os componentes podem ser aplicações, dados ou outros recursos. Cada entidade terá seu próprio domínio e receberá um conjunto comum de atributos de segurança. Por exemplo, considere os níveis de privilégio do processador x86: o kernel do sistema operacional pode rodar no anel 0 (o nível mais privilegiado). Em contraste, as aplicações em modo de usuário podem rodar no anel 3 (o nível menos privilegiado). A separação de domínio está incluída no Modelo Goguen-Meseguer.
2.  **Camadas (Layering):** Quando um sistema é estruturado em muitos níveis abstratos ou camadas, torna-se possível impor políticas de segurança em diferentes níveis; além disso, seria viável validar a operação. Consideremos o modelo OSI (Open Systems Interconnection) com suas sete camadas em redes. Cada camada no modelo OSI fornece serviços específicos para a camada acima dela. Essas camadas tornam possível impor políticas de segurança e validar facilmente que o sistema está funcionando como pretendido. Outro exemplo do mundo da programação são as operações de disco; um programador geralmente usa as funções de leitura e escrita de disco fornecidas pela linguagem de programação de alto nível escolhida. A linguagem de programação oculta as chamadas de sistema de baixo nível e as apresenta como métodos mais amigáveis ao usuário. Camadas se relacionam com Defesa em Profundidade.
3.  **Encapsulamento (Encapsulation):** Na programação orientada a objetos (POO), ocultamos implementações de baixo nível e impedimos a manipulação direta dos dados em um objeto, fornecendo métodos específicos para esse fim. Por exemplo, se você tem um objeto relógio, forneceria um método `increment()` em vez de dar ao usuário acesso direto à variável de segundos. O objetivo é evitar valores inválidos para suas variáveis. Da mesma forma, em sistemas maiores, você usaria (ou até mesmo projetaria) uma Interface de Programação de Aplicativos (API) adequada que sua aplicação usaria para acessar o banco de dados.
4.  **Redundância (Redundancy):** Este princípio garante disponibilidade e integridade. Existem muitos exemplos relacionados à redundância. Considere o caso de um servidor de hardware com duas fontes de alimentação embutidas: se uma fonte de alimentação falhar, o sistema continua a funcionar. Considere uma configuração RAID 5 com três unidades: se uma unidade falhar, os dados permanecem disponíveis usando as duas unidades restantes. Além disso, se os dados forem alterados incorretamente em um dos discos, isso seria detectado através da paridade, garantindo a integridade dos dados.
5.  **Virtualização (Virtualization):** Com o advento dos serviços em nuvem, a virtualização tornou-se mais comum e popular. O conceito de virtualização é compartilhar um único conjunto de hardware entre vários sistemas operacionais. A virtualização fornece capacidades de sandboxing que melhoram os limites de segurança, a detonação segura e a observação de programas maliciosos.

A ISO/IEC 19249 ensina cinco princípios de design:

1.  **Menor Privilégio (Least Privilege):** Você também pode expressá-lo informalmente como “baseado na necessidade” (need-to basis) ou “precisa saber” (need-to-know basis) ao responder à pergunta: “quem pode acessar o quê?” O princípio do menor privilégio ensina que você deve fornecer a menor quantidade de permissões para alguém realizar sua tarefa e nada mais. Por exemplo, se um usuário precisa visualizar um documento, você deve dar a ele direitos de leitura sem direitos de escrita.
2.  **Minimização da Superfície de Ataque (Attack Surface Minimisation):** Todo sistema possui vulnerabilidades que um invasor pode usar para comprometer um sistema. Algumas vulnerabilidades são conhecidas, enquanto outras ainda estão para ser descobertas. Essas vulnerabilidades representam riscos que devemos visar minimizar. Por exemplo, em uma das etapas para proteger um sistema Linux, desabilitaríamos qualquer serviço que não precisássemos.
3.  **Validação Centralizada de Parâmetros (Centralized Parameter Validation):** Muitas ameaças são devidas ao sistema receber entrada, especialmente de usuários. Entradas inválidas podem ser usadas para explorar vulnerabilidades no sistema, como negação de serviço e execução remota de código. Portanto, a validação de parâmetros é uma etapa necessária para garantir o estado correto do sistema. Considerando o número de parâmetros que um sistema manipula, a validação dos parâmetros deve ser centralizada em uma biblioteca ou sistema.
4.  **Serviços Gerais de Segurança Centralizados (Centralized General Security Services):** Como princípio de segurança, devemos visar centralizar todos os serviços de segurança. Por exemplo, criaríamos um servidor centralizado para autenticação. Claro, você pode tomar medidas adequadas para garantir a disponibilidade e evitar a criação de um único ponto de falha.
5.  **Preparação para Tratamento de Erros e Exceções (Preparing for Error and Exception Handling):** Sempre que construímos um sistema, devemos levar em conta que erros e exceções ocorrem e ocorrerão. Por exemplo, em uma aplicação de compras, um cliente pode tentar fazer um pedido de um item fora de estoque. Um banco de dados pode ficar sobrecarregado e parar de responder a uma aplicação web. Este princípio ensina que os sistemas devem ser projetados para falhar de forma segura (fail safe); por exemplo, se um firewall travar, ele deve bloquear todo o tráfego em vez de permitir todo o tráfego. Além disso, devemos ter cuidado para que as mensagens de erro não vazem informações que consideramos confidenciais, como despejar o conteúdo da memória que contém informações relacionadas a outros clientes.
