## Exemplo Prático de Segurança em Aplicações Web

Esta tarefa investigará um site vulnerável que usa Referências Inseguras a Objetos Diretos (IDOR - Insecure Direct Object References). IDOR se enquadra na categoria de Controle de Acesso Quebrado (Broken Access Control). Controle de acesso quebrado significa que um invasor pode acessar informações ou realizar ações não destinadas a ele. Considere o caso em que um servidor web recebe entrada fornecida pelo usuário para recuperar objetos (arquivos, dados, documentos) e que eles são numerados sequencialmente. Digamos que o usuário tenha permissão para acessar uma foto chamada `IMG_1003.JPG`. Podemos supor que também existem `IMG_1002.JPG` e `IMG_1004.JPG`; no entanto, a aplicação web não deve nos fornecer essa imagem, mesmo que tenhamos descoberto seu nome. Em geral, uma vulnerabilidade IDOR pode ocorrer se muita confiança for depositada nesses dados de entrada. Em outras palavras, a aplicação web não valida se o usuário tem permissão para acessar o objeto solicitado.

Apenas fornecer a URL correta para um usuário ou um produto não significa necessariamente que o usuário deva ser capaz de acessar essa URL. Por exemplo, considere a página do produto `https://store.tryhackme.thm/products/product?id=52`. Podemos esperar que esta URL forneça detalhes sobre o produto número 52. No banco de dados, os itens seriam atribuídos a números sequencialmente. O invasor tentaria outros números, como 51 ou 53, em vez de 52; isso poderia revelar outros produtos descontinuados ou não lançados se a aplicação web for vulnerável.

Vamos considerar um exemplo mais crítico; a URL `https://store.tryhackme.thm/customers/user?id=16` retornaria o usuário com id=16. Novamente, esperamos que os usuários tenham números de ID sequenciais. O invasor tentaria outros números e possivelmente acessaria outras contas de usuário. Essa vulnerabilidade pode funcionar com arquivos sequenciais; por exemplo, se o invasor vir `007.txt`, ele pode tentar outros números, como `001.txt`, `006.txt` e `008.txt`. Da mesma forma, se você fosse o ID número 16 e o ID número 17 fosse outro usuário, ao alterar o ID para 17, você poderia ver dados sensíveis que pertencem a outro usuário. Da mesma forma, eles podem alterar o ID para 16 e ver dados sensíveis que pertencem a você. (Claro, assumimos aqui que o sistema é vulnerável a IDOR.)

Clique em “Visualizar Site” (View Site) e vamos ver isso em ação. Você verá uma página mostrando um Sistema de Gerenciamento de Estoque. Se você clicar na aba “Remessas Planejadas” (Planned Shipments), descobrirá que um invasor conseguiu misturar as coisas como parte dos planos de sabotagem. Observe como eles enviam os pneus errados para cada linha de montagem; por exemplo, eles atribuem pneus de scooter e pneus de motocicleta à montagem de bicicletas! Se não for corrigido, todos os pneus irão para a montagem errada.

Vamos hackear o sistema de volta e desfazer os passos do invasor. Em “Sua Atividade” (Your Activity), você pode ver a atividade de um dos usuários. Temos motivos para acreditar que este site possui uma vulnerabilidade IDOR.
